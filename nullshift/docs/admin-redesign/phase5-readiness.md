## Dry-run result (run 17 September 2026)

`pnpm -C apps/web migrations:dry-run` → **0 errors, 3 warnings**, exit 0.

Warnings, all explained and none requiring a migration edit:

1. `0062` line 546 — `drop index if exists public.invoices_one_build_per_project`: the replacement `invoices_one_legacy_build_per_project` is created first in the same transaction and the header documents the equivalent protection (brief §14.2). Rehearse on a branch database because recreating the 0013 index on rollback fails if a project has since gained two live build invoices.
2. Number `0020` is used by two files (`0020_ai_workspace_phases2_5.sql`, `0020_untracked_dpa_columns.sql`) — pre-existing, outside the range, recorded in Phase 0 §3 / N-h.
3. No file numbered `0061` — never assigned on this branch (gap only; harmless, but the ledger entry numbers must be taken from `schema_migrations`, not the directory).

Informational: `0056` has no file on this branch (PR #20's `client_economics` is applied in production); `0062`'s backfill is the only apply-time row mutation (INSERT `billing_obligations`, UPDATE `invoices.obligation_id`, with abort pre-checks and a row-count notice); `0063`'s two tables intentionally have no policies (service role only); `0060`'s `build_acceptances_client_insert` is the one tenant-member write policy; `finance_exceptions_guard` (0065) has no `set search_path` (invoker-rights trigger; acceptable, note for the security review). Apply order: 0057, 0058, 0059, 0060, 0062, 0063, 0064 (after 0059), 0065 (after 0062).

Two heuristics were corrected while building the script (they had produced false positives on 0059 and on header phrases such as "No dependency on 0056"): column definitions are now parsed on top-level commas, and dependencies are read only from the header's DEPENDENCIES section with negated/descriptive sentences removed. No migration was edited.
