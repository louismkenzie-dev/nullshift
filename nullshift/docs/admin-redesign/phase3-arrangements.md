## How to try it

1. Flag off (default): the actions return `{ ok: false, reason: "flag_off" }`; `/admin/next/agreements` is unchanged (still fixtures, not owned by this task).
2. Flag on, on a branch database only: reconcile the ledger (Phase 0 N-h), apply `0059`, set `OPS_V2_FLAGS=commercialV2`. From a server component or route test as staff: `createArrangement({ tenant_id, route: "managed" })` → `package_state = 'pending'`; `draftServiceSchedule({...})` with exact amount/cadence/start/notice and `tax_basis: "exempt"`; `reviewServiceSchedule` **as a different staff user** (same user → `reviewer_is_author`); `issueServiceSchedule` as the author (reviewer as issuer → `review_required`) → snapshot + hash stored; as a `client_admin` member of that tenant, `acceptServiceSchedule({ schedule_id, accepted_by_name, accepted_role, authority_confirmed: true })` → evidence recorded, `package_state = 'accepted'`, no `subscriptions` row. Then mark the Order Form accepted and call `changeArrangementRoute` without `as_variation` → `variation_required`; with it → a new active row and the old one superseded with its schedules intact.
3. Handover: `createArrangement({ route: "independent" })`, `draftHandoverSchedule` (defaults £600/GBP/pending), review, `issueHandoverSchedule` → refused with `tax_basis_pending` + `fee_disposition_pending` until `tax_basis` and `fee_disposition` are set on the draft.
4. Query `service_schedules_client` as the client user: only issued/accepted rows of their own tenant, no reviewer/IP/UA columns; `select * from service_schedules` as that user returns nothing.
